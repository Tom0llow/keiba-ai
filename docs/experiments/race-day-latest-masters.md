# 当日のlatestでの調教と競走馬マスタの差分取得の実測

## 目的と範囲

[ADR-040](../decisions/ADR-040-refresh-workouts-and-horse-master-in-latest.md)で、`--retrieve --mode=latest`の
normalの取得にSLOP・WOOD・DIFNを加え、読込位置の下限（`[latest.normal_start_floors]`、2026-10-01）を設けた。
この記録は、手元の環境で初回の`latest`を1回実行し、所要時間・読込位置・表の最新日付・当日の特徴量の鮮度の前後を示す。

## 実行

2026-11-13 15:54に、race-day-oddsも他の取得も動いていない状態で実行した。

```powershell
uv run python src/main.py --retrieve --mode=latest --data-config <data.toml> --jvlink-config configs/jvlink.toml
```

- 終了コードは0で、`processed snapshot published: 45 tables`を出力した。
- 実行前のruntime設定（`latest.xml`）とCURRENTのsnapshot IDは、実行前に控えた。
- 比べたsnapshotは、実行前のCURRENT`098ce3f4b5d7480282269218d80cef05`と、この実行が公開した
  `b42f68e90d884b1991382e8152c470db`である。下の「実行前」「実行後」は、それぞれこのsnapshotの値である。

## 所要時間

| 段階 | 時間 |
| --- | --- |
| RACEの取得（読込位置2026-10-11から） | 4,839秒。開始からダウンロードの開始（142ファイル）まで約80分、出力がなかった |
| SLOPの取得（下限2026-10-01から、76ファイル） | 3.5秒 |
| WOODの取得（下限2026-10-01から、69ファイル） | 2.9秒 |
| DIFNの取得（下限2026-10-01から、80ファイル） | 8.9秒 |
| 速報系（0B12・0B15・0B11・0B14・0B13・0B17） | 該当データなし（RC=-1）、計0.2秒 |
| JVLinkToSQLite全体 | 4,855秒 |
| snapshotの公開（45表） | 約6,350秒 |

- 長かったのは、元から取得していたRACEの、ダウンロードが始まるまでの待ちと、snapshotの公開である。加えた3種別は計15秒だった。
- RACEは約1か月分たまっていた。毎朝実行したときのRACEの待ちとsnapshotの公開の時間は、この計測からは分からない（#54で測る）。

## 当日の特徴量の鮮度（2026-11-15）

実行後のsnapshotで、2026-11-15を対象に`datamart build-reference-prediction`を実行した（学習用datamart
`reference-datamart-2006-2025`、終了コード0、186秒）。stderrの`freshness`は次のとおりだった。

```text
freshness card_horses=505 card_horses_without_pedigree_row=0 history_held_recent=51 history_held_recent_window_days=7 latest_workout_date={'hc': '2026-11-13', 'wc': '2026-11-13'}
```

- 実行前のsnapshotには2026-11-15の出馬表がないため、同じコマンドでは前の値を作れない。
  前の値は、実行後のsnapshotの2026-11-15の出走馬505頭を、実行前のsnapshotの表に直接照合して求めた。
- 2026-11-15の締切前の市場データはまだないので、36レースすべてが`target_pre_freeze`で保留され、行は0だった。
  この実行は、鮮度を見るためだけのものである。

| 出走馬のうち`NL_UM_UMA`に行がない馬 | 10頭 | 0頭 |

## 結論

- 初回の`latest`は、下限によって2015年からの差分を要求せず、SLOP・WOOD・DIFNを計15秒で取得した。
- 2026-11-15の出走馬について、マスタの欠けがなくなり、調教は実行の当日（2026-11-13）まで更新された。
- 朝の取得の時間の大半は、RACEの待ちとsnapshotの公開で、今回の変更によるものではない。当日の手順での扱いは#54で決める。
