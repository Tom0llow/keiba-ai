# 締切時点のオッズから的中したときの確定オッズへの補正

[ADR-042](../decisions/ADR-042-correct-closing-odds-to-hit-conditional-final-odds.md)の
`model evaluate-final-odds`の使い方と、実データでの結果を記録する。結果は1台のローカル環境での1回の実行であり、
将来の性能や利益の保証ではない。

## 目的と範囲

Issue #35として、freeze（保存した発走予定時刻の5分前、[ADR-041](../decisions/ADR-041-keep-freeze-at-five-minutes-and-present-by-sales-close.md)）
の時点の単勝・複勝・馬連のオッズ`O_z`から、その組合せが的中したときの確定オッズ`E[確定オッズ | 的中]`を
予測する補正を、年単位の拡大型foldで評価する。B4（#36）の期待値は`P(的中) × Ô`で計算するため、
主な指標は払戻の和の比`payout_ratio = Σ(払戻÷100) / ΣÔ`と、比の平均`mean_payout_ratio`である。
補正の成果物の保存と当日の適用（#81）、補正の改良（#82）は扱わない。

## 実行

```powershell
uv run python src/main.py model evaluate-final-odds --config-name measure --override processed_root=<processed root> --output output/final-odds-evaluation-2016-2025
```

- `configs/final_odds_evaluation/evaluate.yaml`はすべて必須値`???`で、`measure.yaml`が計測の前に固定した値
  （train_start_year 2004、test_years 2016〜2025、`max_publication_age_seconds` 600、券種ごとの帯、
  分位点0.1・0.5・0.9、`min_hits` 100、`graded_shrinkage_k` 200、bootstrap 2000回・seed 0・95%）を持つ。
  `snapshot_id: null`はCURRENTを一度だけ固定し、使ったIDを`report.json`の`snapshot`に記録する。
- `--output`は存在しない新しいパスで、親が存在することを要求する。設定の誤りと出力の誤りは、どの表も読む前に拒否する。
- 進捗はstderrに、表と年ごとに
  `phase=publications table=<o1|o2> year=<YYYY> scan_rows=<n> scan_seconds=<s> pairs=<n> rows=<n> read_seconds=<s> seconds=<s>`
  の形で出る。公開に成功した後だけ、stdoutへ要約1行
  `final odds evaluation: <output> races=<n> hits=<単勝>/<複勝>/<馬連> selected=<券種:variant,...> seconds=<s>`
  が出る（採用しない券種は`unadopted`）。失敗した場合（Ctrl+Cを含む）は出力もstagingも残らない。

## 手順

1. 固定snapshotの`NL_RA_RACE`・`NL_HR_PAY`・`ARCHIVE_O1_ODDS_TANFUKUWAKU`・`ARCHIVE_O2_ODDS_UMAREN`のhashを、
   どの行も読む前に取る。最後に`manifest()`で再確認する。
2. `NL_RA_RACE`と`NL_HR_PAY`を、2004-01-01〜2025-12-31・中央01〜10場で読む。`NL_RA_RACE`の`GradeCD`
   （A・B・C）と`TrackCD`（10〜24）で平地重賞`jra_flat_graded_stakes_v1`を判定する。
3. O1・O2は年ごとに、キー・区分・`HappyoTime`だけを読み（pass 1）、各レースのfreeze以前の最新の中間発表の
   時刻（衝突と不正な時刻も含む）を選び、選んだ（レース, 発表時刻）の行だけを読む（pass 2）。
   全行を読んだ場合と同じ`latest_o1`の結果になる。
4. レースごとに的中の観測（`O_z`、払戻÷100）、保留、除外を組み立てる。
5. test年`Y`ごとに2004〜`Y−1`の的中で`all`（全レース）と`graded`（重賞、`all`へ縮小）を当てはめ、`Y`の的中で採点する。
   `none`は補正しない`O_z`である。
6. 全test年と2016〜2020年をまとめ、レース単位のbootstrapで区間を求め、重賞の全test年の区間に、計測の前に固定した
   採否の規則（ADR-042の決定6）を当てる。

## 解釈

- 補正しない`O_z`は、複勝で偏りが大きい。`OddsLow`は重賞で確定を約18%低く見積もり（`payout_ratio` 1.216）、
  `√(OddsLow·OddsHigh)`は約2%高く見積もる。補正はこの偏りを除き、誤差の中央値も下げる。
- 単勝と馬連では、補正は`mean_payout_ratio`を1へ近づけるが、`payout_ratio`は1より小さいままである（単勝で約4%、
  馬連で約8%高く見積もる）。`payout_ratio`は高い配当の的中に重みがかかり、差は高いオッズの帯から来る。
  全レースでは単勝の30倍以上の的中の確定がfreezeより上がる（補正しない帯の`payout_ratio`が1.05〜1.26）が、
  重賞では上がらない（30〜100倍で0.97〜1.03）。帯の倍率は全レースの値に近い（`graded`も重賞の的中が少なく、
  `k`=200で全レースへ縮小される）ため、重賞の高い帯を高く見積もる（`all`の`payout_ratio`は単勝20倍以上で
  0.90〜0.95、馬連100倍以上で0.76〜0.95）。
- 重賞は全レースより確定までの変動が小さい（単勝の誤差の中央値は重賞で4.8〜5.2%、全レースで8.7〜9.1%）。
- 10〜90%区間の被覆は0.8になるはずだが、全レースの馬連で0.57、単勝で0.73と低い。2004年からの学習の的中より、
  test年の確定までの変動が大きい。学習の窓（直近の年だけ）の比較は#82で扱う。
- 採否の結果は期間で変わり、`place_mid`の`all`と`graded`の差（重賞の`mean_payout_ratio`で0.018）は小さい。
  B4（#36）で期待値に使う場合は、`place_mid`の`graded`を採るのが固定した規則の結果だが、
  単勝・馬連の`Ô`をそのまま使うと期待値を数%高く見積もることに注意する。どう使うかは#36で決める。

## 限界

- 1回の実行で、1つのsnapshotだけを使った。bootstrapはレース単位で、年の間の変化は区間に含まない。
- freezeは保存した`HassoTime`の5分前で、発走時刻の変更は反映しない（ADR-041）。
- 帯・分位点・縮小の強さ・`min_hits`は計測の前に固定した値で、探索はしていない。
- 複勝の`place_mid`は`OddsLow`と`OddsHigh`の幾何平均で、確定の払戻の決まり方を直接は表していない。
- 複勝の通常の払戻の件数は`NL_HR_PAY`の`SyussoTosu`（出走頭数）で決めている。42レースでは払戻の件数がこの規則より多く
  （41レースは`SyussoTosu`が6〜7で3件、1レースは4で2件。どれも`TorokuTosu`のほうが多く、発売後の取消・除外で
  頭数が減ったとみられる）、その複勝の的中（`place_low`・`place_mid`それぞれ約125件）を同着として除いている。
  上の同着847件に含まれる。複勝の的中の約0.05%で、指標への影響は小さい。
