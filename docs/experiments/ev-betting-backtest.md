# 期待値による単勝・複勝の購入方策のバックテスト

[ADR-043](../decisions/ADR-043-fix-an-expected-value-win-and-place-policy-and-backtest-graded-races.md)の
`model backtest-betting`の使い方と、実データでの結果を記録する。結果は1台のローカル環境での1回の実行であり、
将来の性能や利益の保証ではない。仮想購入であり、システムは購入を実行しない。

## 目的と範囲

Issue #36として、PLの着順確率（[ADR-035](../decisions/ADR-035-evaluate-top3-plackett-luce-probabilities-on-yearly-folds.md)の
test年ごとのfoldの予測）と、確定オッズの補正（[ADR-042](../decisions/ADR-042-correct-closing-odds-to-hit-conditional-final-odds.md)）から
単勝・複勝の買い目の期待値を計算し、REQ-04〜06の予算を守る方策で平地重賞の過去の購入時点（freeze、発走5分前）を再現して評価する。
方策は計測の前に固定し、評価期間の結果で値を変えない。当日の購入案への適用（#81）と実購入額の管理（#56）は扱わない。

## 実行

```powershell
uv run python src/main.py model backtest-betting --config-name measure --override processed_root=<processed root> --override pl_evaluation_path=<PLの評価の出力> --override pl_predictions_sha256=<SHA-256> --override pl_report_sha256=<SHA-256> --output output/ev-betting-backtest-2016-2025
```

- `configs/betting_backtest/evaluate.yaml`はすべて必須値`???`で、`measure.yaml`が計測の前に固定した値を持つ。
  - 方策: 単勝・複勝、期待受取倍率`R = P × Ô`が1.10以上、1/4ケリー、基準資金・年間の枠100,000円、1レース5,000円、100円単位。
  - 複勝の補正: ADR-042の`measure.yaml`と同じ値（train 2004〜、`place_mid`の帯、分位点、`min_hits` 100、`k` 200、
    `max_publication_age_seconds` 600）。
  - bootstrap: 2,000回、seed 0、95%。
- PLの評価の`report.json`・`predictions.parquet`はSHA-256で固定する。reportが記録する重賞の出典のsnapshotを使い、その
  `NL_RA_RACE`のSHA-256がreportと一致することを要求する。datamartの保留の理由は、reportが指すdatamartのmanifestと
  `held_races.json`をhashで確かめてから読む。datamartがない・一致しない場合は実行を止める。
- `--output`は存在しない新しいパスで、親が存在し、`processed_root`・PLの評価・datamart・固定snapshotのディレクトリの外にあること。
  設定・出力・PLの2ファイルのhashの誤りは、snapshotのどの表も読む前に拒否する（datamartとsnapshotの中の出力は、
  それらを指すPLの評価の`report.json`を読んだ後に拒否する）。
- 進捗はstderrへ、公開に成功した後だけstdoutへ要約1行
  `ev betting backtest: <output> graded_races=<n> purchased_races=<n> stake_yen=<円> receipt_yen=<円> recovery_rate=<比> seconds=<s>`
  が出る。失敗した場合（Ctrl+Cを含む）は出力もstagingも残らない。

## 手順

1. PLの評価の2ファイルのhashを照合し、reportから重賞の出典のsnapshotとdatamartを決める。
2. 固定snapshotの`NL_RA_RACE`・`NL_SE_RACE_UMA`・`NL_HR_PAY`・`ARCHIVE_O1_ODDS_TANFUKUWAKU`のhashを、どの行も読む前に取る。
   最後に`manifest()`で再確認する。
3. datamartの保留（`role="target"`）と、PLの予測（`finish_position`と`score`は読まない）を読み、予測を検査する
   （確率の範囲・`p_win ≤ p_top2 ≤ p_top3`・レース内の和・test年）。
4. 2004〜2025年の`NL_RA_RACE`・`NL_HR_PAY`と、test年の重賞の`NL_SE_RACE_UMA`を読む。O1は年ごとにADR-042と同じ2 passで読み、
   全レースの`place_mid`の的中の観測を組み立てる。
5. test年`Y`ごとに、2004〜`Y−1`の的中で`place_mid`の`graded`補正を当てはめる。
6. test年の重賞ごとに、freezeのO1（`latest_o1`）、出走表の馬番の対応、予測を照合し（集合・単勝オッズの不一致は保留）、
   単勝（`Ô = O`）と複勝（`Ô`は補正、頭数8以上は`p_top3`、5〜7は`p_top2`）の候補を作る。
7. freezeの順に方策を当て（要求額、レースと暦年の上限による縮小）、購入したレースを確定の払戻で精算する。
8. 暦年ごとと全test年の指標、件数、`bets.parquet`・`races.parquet`を組み立てて公開する。

## 入力と件数

- PLの評価: `output/pl-evaluation-2016-2025-graded-final3`（test 2016〜2025、variant`all_columns`）。
  `predictions.parquet`のSHA-256 `d73419d2…0dcb`、`report.json`のSHA-256 `2b26ad30…9611`。
- 固定snapshot: `098ce3f4b5d7480282269218d80cef05`（PLのdatamartと同じ。ADR-042の計測の`034f3ff2…`とは異なる）。
- 対象の平地重賞: 1,289レース（年127〜130）。予測あり1,103レース。
- 予測のない重賞: 186レース。datamartの保留の段階は、結果に基づく保留（`target_outcome`）139、freeze前の保留
  （`target_pre_freeze`）47。その他・帰属なしは0件。
- 予測のあるレースの保留（freeze・O1・出走表・単勝オッズの不一致）: 0件。複勝を買えない頭数（4頭以下）: 0件。
- 候補がなく見送り: 177レース。購入: 926レース（うち上限で縮小41）。年間の枠が尽きたレース: 0件。返還のあった買い目: 0件。

## 所要時間

計158秒（Windows 11、Python 3.12）。PLの予測の読込と検査が約3秒、`NL_RA_RACE`・`NL_HR_PAY`・`NL_SE_RACE_UMA`の読込が約5秒、
O1の読込（22年、pass 1が計109秒・996万行、pass 2が計10秒）と的中の観測の組み立てが約143秒、補正・購入・精算・指標が約7秒。

## 解釈

- 固定した方策は、2016〜2025年の重賞で回収率81.0%（95%区間0.670〜0.963）で、REQ-02の目標（暦年100%以上）に届かない。
  区間の上限が1を下回るため、この方策での購入は損失になると判断する。
- 損失の主な原因は、方策が選ぶ買い目での確率とオッズの見積もりの偏りである。期待値の高い買い目を選ぶと、確率を過大に、
  あるいはオッズを過大に見積もった買い目が集まる（選択による偏り、ADR-042・ADR-043のRisks）。
  - 単勝は高いオッズの馬の`P`が過大で、期待的中数の約6割しか的中しなかった。PLの評価でも、`all_columns`は全レースの単勝の
    Log Lossで市場に及ばず、重賞では差が確認できなかった（ADR-035の記録）。
  - 複勝の`Ô`は`√(OddsLow·OddsHigh)`に全的中の平均の倍率を掛けたもので、選ばれる馬（他の人気馬と同時に3着以内に入りやすい）
    では払戻が下限側に寄る。
- 年ごとの変動は大きく、2025年は86レースで的中2・最大連敗77だった。暦年の回収率の区間は広く、1年の結果からは方策の
  良否を判断できない。
- この結果は、運用での購入の開始の根拠にならない。PLの確率の改善（単勝の高いオッズ帯の校正）と、選ばれる買い目での
  オッズの見積もりの改善（#82）を、評価期間を使わない設計で検討する必要がある。

## 限界

- 1回の実行で、1つのsnapshotとPLの評価の1つの出力だけを使った。bootstrapは購入レースを単位とし、予算の経路（縮小・枠）と
  年の間の変化は区間に含まない。
- PLの予測がない重賞186レース（約14%）を評価から外した。そのうち139レースは結果に基づく保留（同着・異常区分など）で、
  運用では予測・購入するはずのレースである。この欠落による偏りの向きは分からない。
- freezeは保存した`HassoTime`の5分前で、発走時刻の変更は反映しない（ADR-041）。当日は発表が遅れて古いオッズを使うことがある（#78）。
- 方策の値（`R`の閾値、ケリーの係数）は計測の前に固定した値で、探索はしていない。単勝と複勝の相関や、年間の枠の配分は
  最適化していない。
- 手数料を含まない。収支は純利益ではない。
- 特払い・不成立の旗のある重賞への購入はなく、その精算の規則は確かめていない。
