# top-3 Plackett–Luceの着順確率モデルの評価

[ADR-035](../decisions/ADR-035-evaluate-top3-plackett-luce-probabilities-on-yearly-folds.md)の
`model evaluate-pl`の使い方、出力形式、実データでの結果を記録する。入力は
[ADR-034](../decisions/ADR-034-build-full-period-reference-feature-datamart.md)の参考datamart
（[構築と計測](reference-feature-datamart.md)）である。結果は1台のローカル環境での1回の実行であり、
将来の性能や利益の保証ではない。

## 目的と範囲

Issue #34として、top-3 PLの負の対数尤度をLightGBMで学習し、年単位の拡大型fold（train〜Y−2・
valid Y−1・test Y）で、validによるearly stoppingと温度の校正を行い、testで同時点の市場確率
$q_i=(1/O_i)/\sum_j(1/O_j)$と比較する。購入判断（#36）、LambdaRankとの比較（#48）、2・3着の
偏りの補正（#49）は扱わない。

## 実行

```powershell
uv run python src/main.py model evaluate-pl --config-name measure --override processed_root=<processed root> --override datamart_path=<datamart> --override datamart_manifest_sha256=<manifestのSHA-256> --output output/pl-evaluation-2016-2025
```

- `configs/pl_evaluation/evaluate.yaml`はすべて必須値`???`で、`measure.yaml`が実データ用の明示値
  （train_start_year 2006、test_years 2016〜2025、variant 2通り、LightGBMの設定、bootstrap 2000回）を持つ。
  processed root、datamartのパスとSHA-256は`--override`で渡す。SHA-256は`datamart build-reference`の要約の値である。
- datamart manifestの`snapshot_id`で固定snapshotを開き、`target_period`と参考規則の`venues`に限定して
  `NL_RA_RACE`の`GradeCD`・`TrackCD`を読む。読込後の表hashがdatamart manifestの出典と一致しない場合、
  testレースがsnapshotに無い場合、fold年がdatamartの対象期間の外にある場合、`train_start_year`が
  test年−2より後の場合、全列を除くvariantがある場合は、datamartの全体の読込の前に評価を開始しない。
- variantは`all_columns`（全36列）と`without_market`（`market_characteristics__market_win_odds`を除く35列）。
  どちらも$q_i$との比較には同じ単勝オッズ列を使う。
- `--output`は存在しない新しいパスで、親が存在することを要求する。進捗はstderrに
  `phase=fold variant=<name> test_year=<YYYY> best_iteration=<n> temperature=<T> fold_seconds=<s> seconds=<s>`の形で出る。
  `fold_seconds`はそのvariant×foldの学習・校正・採点の時間、`seconds`はどの行でもコマンドの開始からの経過時間である。
  公開に成功した後だけ、stdoutへ要約1行が出る。失敗した場合（Ctrl+Cを含む）は出力もstagingも残らない。

## 手順

1. datamart manifestの`snapshot_id`で固定snapshotを開き、対象期間・venueの`NL_RA_RACE`を読み、表hashを照合する。
   設定・fold年・variantを検査した後、test年の`races.parquet`をmanifestのSHA-256で照合して`race_id`列だけを読み、
   snapshotに無いtestレースを拒否し、datamartに無い平地重賞の件数をtest年ごとに数える。
   続けてdatamartをmanifestのSHA-256で固定して読み、hash・schema・時点・ラベル境界を検証する（21群は再計算しない）。
2. test年ごとに、train・valid・testのレースを年（`scheduled_start_at`のJST）で分ける。
   `label_usable_after`がvalid（またはtest）の最初のfreeze以後のtrain（またはvalid）のレースを除く。
3. trainで学習し、validのレース平均top-3 NLLでearly stoppingする。
4. validのtop-3 NLLを最小にする単一の温度$T$を求める。
5. testで、校正前（raw）と校正後（calibrated）の確率と指標を出す。市場完全レース（全馬の単勝オッズが
   有限かつ正）では$q_i$と、連勝式は$q_i$からのHarville展開と比べる。testの着順は採点だけに使う。

## 出力

```text
<output>/
├─ report.json          # 設定、datamart・部分集合の識別、provenance、foldごと・pooledの指標・比較・校正表
└─ predictions.parquet  # testの馬ごと: variant、test_year、race_id、horse_id、finish_position、
                        # score、temperature、p_win・p_top2・p_top3（校正後）、market_win_odds、market_q、
                        # in_jra_flat_graded_stakes
```

- `report.json`のformatは`pl_probability_evaluation`、format_versionは1である。
- `report.json`のトップに`race_subsets.jra_flat_graded_stakes_v1`として、GradeCD A/B/CかつTrackCD 10〜24の
  定義（`definition`）、`NL_RA_RACE`・SHA-256・`snapshot_id`の出典（`source`）、test年ごとの、snapshotにあって
  datamartに無い（保留された）部分集合のレース数（`not_in_datamart_by_test_year`）を持つ。foldごと・variantごと・
  pooledには部分集合ごとの件数、指標、市場比較、校正表を持つ。
- `market_complete_races.calibration`の形は2通りある。全testレースの`variants.<name>.market_complete_races`では
  モデル（校正後）の`{win, top2, top3}`の表で、市場の表はfoldの`market_calibration`にある。部分集合の
  `subsets.<name>.market_complete_races`では`{calibrated_model: {win, top2, top3}, market: {win, top2, top3}}`の
  モデルと市場の組である。
- foldごとに、件数（train・valid・testのレースと行、除外件数、市場完全・不完全のレース数）、
  ラベル監査値、市場の指標と校正表、variantごとの`best_iteration`・温度推定・特徴量名・指標・比較・
  校正表を持つ。`pooled`は全foldのtestレースをまとめた指標と比較である。
- 指標は勝者のLog Loss、多クラスBrier、馬単・馬連・3連単・3連複のLog Loss、着順段階別のNLLで、
  レースを等しい重みとする。比較はモデルと市場のレースごとの差の平均と95%区間、判定
  （`model_better`・`market_better`・`inconclusive`）である。校正表は馬を等しい重みとする。
- `market_q`は市場完全でないレースではnullである。
- `predictions.parquet`の`in_jra_flat_graded_stakes`はboolでnullを持たず、部分集合判定はtestの着順を使わない。

## 実データでの結果

2026-11-09〜10に、snapshot `098ce3f4b5d7480282269218d80cef05`から構築した全期間datamartで評価した。
環境はWindows 11、Intel Core i5-14400F（16論理コア）、物理メモリ32GB、NVMe SSD、Python 3.12である。
時間・CPU時間・ピークメモリは、インタープリタ自身を`ctypes`の`K32GetProcessMemoryInfo`と`GetProcessTimes`で測った。

- datamartの構築は20年、59,115レース、835,398行で、保留は21,150件（`history_result` 10,836、
  `target_outcome` 7,961、`target_pre_freeze` 2,353、`calculation` 0）だった。manifestのSHA-256は
  `dc37514732fdb653ce9ed3a6e836a0f6f120a5613a905c5574d43cdc0f4b51b9`、ディスク上は71MBである。
  対象年の処理は1年あたり、1回目は301秒（2006年）から747秒（2025年）、2回目は289秒から658秒で、
  履歴が長くなるにつれておおむね増えた（2019年など一部の年は前年より短い）。
- 1回目の構築ではCPU時間とピークメモリを取れなかった。計測用の小さなwrapperの不具合で、ctypesの
  型宣言が漏れてWindows APIの呼出しが失敗し、0を出したためである。wrapperを直して確かめた後に、
  評価と、同じ設定・同じsnapshotでの2回目の構築を測った。
- 1回目は、全体の検証・レビュー・ベンチマークと同時に動いていたため遅い。2回目は、開始直後の数分を除いて
  他の処理と重ならず、単独の実行に近い。
- 2回の構築で、年ごとのParquet（20年分の`part-0.parquet`と`races.parquet`）と`held_races.json`の
  SHA-256、計算契約、列一覧はすべて一致した。manifestで異なったのは、コードの識別情報（provenance）
  だけである。2回目のmanifestのSHA-256は
  `35efdf31f629d5eb10da83631508a25350f1cf45373d78692fe0d8e548228d69`である。評価には1回目のdatamartを使った。
- 上の評価は、レビューで修正する前のコードで実行した。レビューでの修正（校正の帯の検証、市場完全レースに
  限ったモデルの校正表の追加）の後に、同じdatamart・同じ設定で評価をもう一度実行し、`predictions.parquet`の
  全行、foldごと・pooledの指標と比較が完全に一致することを確かめた。異なったのはコードの識別情報
  （provenance）と、追加した`market_complete_races.calibration`だけである。この再実行は1,165秒、CPU時間
  8,234秒、ピーク作業セット1.95GB、ピークcommit 3.56GBだった。
- 評価では、datamartの読込と検証が約52秒、1回の学習・校正・採点が31〜90秒だった。`best_iteration`は
  `all_columns`で147〜351、`without_market`で363〜702である。出力は`report.json`が0.5MB、
  `predictions.parquet`が37.7MBだった。

### foldの件数とラベル利用境界

- 各foldのtestは2,840〜3,053レースで、10 fold合計29,754レースである。全testレースが市場完全だった
  （単勝オッズの欠損は0レース）。
- 除外はtest 2016のfoldのtrainの19レースだけだった（`label_usable_after`がvalidの最初のfreeze以後）。
  validからの除外は全foldで0である。
- 全foldで、trainの最大`label_usable_after` < validの最初のfreeze、trainとvalidの最大 < testの最初の
  freezeが成り立った。例えばtest 2025では、validの最大が2025-01-04 15:00 UTC（JST 2025-01-05 0時）、
  testの最初のfreezeが2025-01-05 00:45 UTCである。
- 温度は`all_columns`で0.990〜1.029、`without_market`で0.962〜1.045で、どれも範囲の境界に張り付いて
  いない。校正前後の差は小さい。

### 解釈と注意

- 市場列を含むモデルは、この評価母集団では単勝で市場に及ばない（pooledで勝者のLog Lossが0.0102悪い）。
  この評価母集団での市場超過の証拠はない。
- 連勝式でモデルが上回った差は2着・3着の段階に集まっており、比較相手がHarville展開であることが大きく
  効いていると解釈する。市場のHarville展開は2着・3着の段階別NLLが悪い。モデルの本命の過小評価は、2・3着を含むtop-3の尤度が1着の確率を平らにすることに加え、
  early stoppingや正則化が寄与する仮説がある。この1回の評価だけでは原因を分離できないため、#49で
  アブレーションにより検証する。
