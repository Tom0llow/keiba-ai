# top-3 Plackett–Luceの着順確率モデルの評価

[ADR-035](../decisions/ADR-035-evaluate-top3-plackett-luce-probabilities-on-yearly-folds.md)の
`model evaluate-pl`の使い方、出力形式、実データでの結果を記録する。入力は
[ADR-034](../decisions/ADR-034-build-full-period-reference-feature-datamart.md)の参考datamart
（[構築と計測](reference-feature-datamart.md)）である。結果は1台のローカル環境での1回の実行であり、
将来の性能や利益の保証ではない。

## 目的と範囲

Issue #34として、top-3 PLの負の対数尤度をLightGBMで学習し、年単位の拡大型fold（train〜Y−2・
valid Y−1・test Y）で、validによるearly stoppingと温度の校正を行い、testで同時点の市場確率
$q_i=(1/O_i)/\sum_j(1/O_j)$と比較する。購入判断（#36）、LambdaRankとの比較（#48）、2・3着の
偏りの補正（#49）は扱わない。

## 実行

```powershell
uv run python src/main.py model evaluate-pl --config-name measure --override datamart_path=<datamart> --override datamart_manifest_sha256=<manifestのSHA-256> --output output/pl-evaluation-2016-2025
```

- `configs/pl_evaluation/evaluate.yaml`はすべて必須値`???`で、`measure.yaml`が実データ用の明示値
  （train_start_year 2006、test_years 2016〜2025、variant 2通り、LightGBMの設定、bootstrap 2000回）を持つ。
  datamartのパスとSHA-256は`--override`で渡す。SHA-256は`datamart build-reference`の要約の値である。
- variantは`all_columns`（全36列）と`without_market`（`market_characteristics__market_win_odds`を除く35列）。
  どちらも$q_i$との比較には同じ単勝オッズ列を使う。
- `--output`は存在しない新しいパスで、親が存在することを要求する。進捗はstderrに
  `phase=fold variant=<name> test_year=<YYYY> best_iteration=<n> temperature=<T> fold_seconds=<s> seconds=<s>`の形で出る。
  `fold_seconds`はそのvariant×foldの学習・校正・採点の時間、`seconds`はどの行でもコマンドの開始からの経過時間である。
  公開に成功した後だけ、stdoutへ要約1行が出る。失敗した場合（Ctrl+Cを含む）は出力もstagingも残らない。

## 手順

1. datamartをmanifestのSHA-256で固定して読み、hash・schema・時点・ラベル境界を検証する
   （21群は再計算しない）。
2. test年ごとに、train・valid・testのレースを年（`scheduled_start_at`のJST）で分ける。
   `label_usable_after`がvalid（またはtest）の最初のfreeze以後のtrain（またはvalid）のレースを除く。
3. trainで学習し、validのレース平均top-3 NLLでearly stoppingする。
4. validのtop-3 NLLを最小にする単一の温度$T$を求める。
5. testで、校正前（raw）と校正後（calibrated）の確率と指標を出す。市場完全レース（全馬の単勝オッズが
   有限かつ正）では$q_i$と、連勝式は$q_i$からのHarville展開と比べる。testの着順は採点だけに使う。

## 出力

```text
<output>/
├─ report.json          # 設定、datamartの識別、provenance、foldごと・pooledの指標・比較・校正表
└─ predictions.parquet  # testの馬ごと: variant、test_year、race_id、horse_id、finish_position、
                        # score、temperature、p_win・p_top2・p_top3（校正後）、market_win_odds、market_q
```

- `report.json`のformatは`pl_probability_evaluation`、format_versionは1である。
- foldごとに、件数（train・valid・testのレースと行、除外件数、市場完全・不完全のレース数）、
  ラベル監査値、市場の指標と校正表、variantごとの`best_iteration`・温度推定・特徴量名・指標・比較・
  校正表を持つ。`pooled`は全foldのtestレースをまとめた指標と比較である。
- 指標は勝者のLog Loss、多クラスBrier、馬単・馬連・3連単・3連複のLog Loss、着順段階別のNLLで、
  レースを等しい重みとする。比較はモデルと市場のレースごとの差の平均と95%区間、判定
  （`model_better`・`market_better`・`inconclusive`）である。校正表は馬を等しい重みとする。
- `market_q`は市場完全でないレースではnullである。

環境はWindows 11、Intel Core i5-14400F（16論理コア）、物理メモリ32GB、NVMe SSD、Python 3.12である。

### foldの件数とラベル利用境界

- 各foldのtestは2,840〜3,053レースで、10 fold合計29,754レースである。全testレースが市場完全だった
  （単勝オッズの欠損は0レース）。
- 除外はtest 2016のfoldのtrainの19レースだけだった（`label_usable_after`がvalidの最初のfreeze以後）。
  validからの除外は全foldで0である。
- 全foldで、trainの最大`label_usable_after` < validの最初のfreeze、trainとvalidの最大 < testの最初の
  freezeが成り立った。例えばtest 2025では、validの最大が2025-01-04 15:00 UTC（JST 2025-01-05 0時）、
  testの最初のfreezeが2025-01-05 00:45 UTCである。
- 温度は`all_columns`で0.990〜1.029、`without_market`で0.962〜1.045で、どれも範囲の境界に張り付いて
  いない。校正前後の差は小さい。

| [3, 5) | 32,108 | 0.1914 | 0.2044 | 0.2107 |

- モデルの勝率は本命を低く、人気薄（単勝オッズ10倍以上）を高く見積もる。予測勝率の帯で見ても、[0.3, 0.5)では予測の平均0.370に

### 解釈と注意

- 市場列を含むモデルは、この評価母集団では単勝で市場に及ばない（pooledで勝者のLog Lossが0.0102悪い）。
  この評価母集団での市場超過の証拠はない。
- 連勝式でモデルが上回った差は2着・3着の段階に集まっており、比較相手がHarville展開であることが大きく
