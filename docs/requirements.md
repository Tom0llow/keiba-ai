# 競馬AI 要件定義

状態: 合意済み要件の正本（2026-10-06）。これは開発対象と達成したい結果を定める文書であり、実装済みの機能や収益の保証を示さない。確定した振る舞いは[仕様書](specification.md)に記す。議論の経緯は[要件検討](discussions/2026-10-02-keiba-ai-requirements.md)と[モデル設計レビュー](discussions/2026-10-03-model-architecture-review.md)に残す。

## 目的と対象

| ID | 要件 |
| --- | --- |
| REQ-01 | 対象はJRAの平地重賞（G1・G2・G3）とする。障害重賞、地方競馬、海外競馬は購入提案の対象外とする。 |
| REQ-02 | 暦年（1月～12月）の馬券回収率100%以上を目標とする。これは検証・運用で評価する目標であり、達成を保証する受入条件ではない。 |
| REQ-03 | 同じ判断時点の市場オッズを基準として、それより高精度な確率推定を目指し、実測で比較する。確率推定の改善と購入による利益は別々に検証する。 |

## 購入と利用者

| ID | 要件 |
| --- | --- |
| REQ-04 | 暦年の馬券購入額累計を100,000円以内にする。払戻金を得てもこの購入額上限は増やさない。データ契約費はこの枠に含めない。 |
| REQ-05 | 1レースの全買い目の購入額合計を5,000円以内にする。 |
| REQ-06 | 期待利益が見込めない場合は購入を見送れるようにする。期待利益と損失リスクの両方を考慮する。年間購入額上限とは別の純損失による途中停止条件は設けない。 |
| REQ-07 | 購入案を発走5分前までに提示し、購入は利用者が行う。システムによる自動購入は求めない。 |
| REQ-08 | 単勝、複勝、馬連、馬単、ワイド、3連複、3連単を初期の調査・比較対象に含める。全券種を最初の実運用対象とする意味ではない。 |

## 予測・データ・検証

| ID | 要件 |
| --- | --- |
| REQ-09 | 開発順は「データの時点確認と勝敗要因の探索 → 市場オッズによる基準方法 → LambdaRankによるランキングMVP → top-3 Plackett–Luceによる着順確率モデル → 買い目と購入額の最適化」とする。 |
| REQ-10 | 発走前の判断に、その時点で利用できなかった結果・オッズ・その他の情報を使わない。過去データの評価も購入時点を再現して行う。 |
| REQ-11 | ランキングMVPはNDCG@3を主指標、Top1精度とTop3一致割合を補助指標として評価する。確率モデルへの拡張ではLog Loss・Brier Score・確率校正も評価する。同じ判断時点の市場基準と比較し、購入結果は回収率、年間利益、購入レース数、的中率、最大ドローダウン、最大連敗、資金推移で別に評価する。評価対象の重賞レースを学習・調整に流用しない、レース単位の時系列検証とする。 |
| REQ-12 | `data/raw/race.db` は利用中のJVLinkToSQLiteが生成した原本である。追加データが必要なら有料契約も検討できる。ただし、現在取得できる発走前オッズ履歴や利用権の範囲は未確認である。 |

## 要件を満たしたか判断する際の境界

年間上限は口座残高や年間純損失ではなく、購入した馬券の**額面の累計**で判定する。したがって払戻があっても購入可能枠は戻らない。1レース上限は券種や買い目をまたぐ合計で判定する。提案と実際の購入が異なる可能性があるため、運用時の予算判定には実購入額の把握が必要となる。

回収率と純利益の集計式、返還・特払い・手数料の精算規則は[仕様書](specification.md)と[ADR-009](decisions/ADR-009-use-lambdarank-mvp-and-top3-pl-extension.md)に定める。評価に必要な期間や許容する不確実性、購入経路固有の手数料は未決定である。利益目標の数値を満たすことを実装完了の判定条件にはしない。

ランキングMVPは上位馬の並び順を学ぶ段階とし、順位付けスコアを勝率や連勝式確率とはみなさない。Top1精度は予測首位が実際の勝者だったレースの割合、Top3一致割合は予測上位3頭と実際の上位3頭の共通頭数を3で割った値のレース平均とする。MVPは確率・期待値・購入案を出さず、REQ-03の確率推定と購入要件の検証はPL拡張以降に行う。

## まだ確定していない事項

LambdaRankのランキングMVPとtop-3 PLによる確率モデルへの拡張方針は[ADR-009](decisions/ADR-009-use-lambdarank-mvp-and-top3-pl-extension.md)で選定済みである。入力特徴量、学習対象の範囲、ハイパーパラメータ、PLの具体的なcustom objectiveと校正方法、同着・取消等のラベル・評価・購入判断の扱いは実装前に定める。リスク尺度と許容値、購入経路・表示形式、発走5分前の提示に間に合わせる入力固定時刻、発走前オッズ履歴の保存状況は未決定である。Closing Odds Model、Fractional Kelly、強化学習、Jevなどは採用を決めていない。以前の論点と比較は[モデル設計レビュー](discussions/2026-10-03-model-architecture-review.md)に残し、今後の選定を仕様書または必要なADRへ反映する。
