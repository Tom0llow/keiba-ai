# ADR-028: 時点証跡付き原観測から21群を計算する

- Status: Accepted
- Date: 2026-10-22
- Decision Owners: Repository maintainers
- Supersedes: ADR-019/020から継承する「業務値は外部計算済み入力だけ」の制限のみ
- Superseded by: N/A

## Context

ユーザーは既存特徴量を使う学習・予測を求め、実装調査後に「21群すべての計算を先に実装する」
「厳格な時点証拠をそろえてから実データ学習する」と選択した。
F01〜F21の既存APIは計算済み値の監査・保存を行うが、履歴集計等の計算は実装していない。
現行Parquetには過去の受信・訂正・固定出馬表の証跡がなく、これを時刻の仮置きで補うことはできない。
既存の明示値API、時点監査、モデルの数値allow-listと保存形式は保持する必要がある。

## Decision

1. 各既存の特徴量ファイルへ `calculate_*` を追加する。`build_*` は計算済み明示値を受け取る
   既存の契約を維持し、計算APIは正規化済みの原観測と明示パラメータから実値を求める。
   新しい計算式は各特徴量ファイルが所有し、一つの巨大な業務計算モジュールへ集約しない。
2. `make_features/contracts/` が正規化済み出馬表・通常結果全馬・距離付きラップ/調教・
   父/母父・発売対象とオッズ・履歴完全性・出典証跡、計算パラメータと結果を定義する。
   出馬表には当該結果を持たせない。予定発走時刻と、その予定を知った時刻を区別する。
   原観測の識別子、版、内容hash、出典、発表・受信時刻と全依存を保持する。
3. `validation/` が証跡、対象集合・キー・結果の完全性、改訂の競合、時点を検証する。
   `generation/` がas-of履歴選択、窓、共通統計と薄い全体計算を所有する。
   入力の将来版を過去の計算へ利用せず、対象結果を履歴へ入れない。
   対象レースより前のJST暦日の履歴に限定し、同日順序をレースIDで補わない。
   過去行の基準・prior・グラフも当該行の時点より前の利用可能な結果から求める。
4. 正規化済み入力の意味・単位は型契約へ明記する。raw列からのコード・倍率・血統配列・
   ラップ区間の解釈は計算モジュールに持ち込まない。原列名から推測しない。
   発表・受信・改訂の証跡が欠けるデータは具体的な不足を示して拒否し、全欠損の成功へ変換しない。
5. 出力には群別の値、規則ID、使用した全観測参照と依存時刻、欠損理由、件数を保持する。
   既存の `FeatureBatchInput` / `FeatureGroupInput` へ投影して共通監査・中間表生成を再利用する。
   群の `available_at` は全依存の最大、`source_event_at` は観測事象の最大とする。
   混合依存は詳細証跡に残し、既存scopeへ表現できない情報を捨てない。
6. 計算対象の式は[実装設計7.2〜7.4](../implementation-design.md#7-特徴量の設計候補と加工判断)の
   共通定義と下表を具体化する。将来のモデル採用や全列の自動投入を意味しない。

| 群 | 実装する計算 |
| --- | --- |
| F01 | 過去着順・相対着順のlag、勝率/top3率、窓内件数。 |
| F02 | 過去の時計・符号付き着差・速度・上がりの順位と相対順位。 |
| F03 | 自身を含まない過去勝者基準による時間/速度補正、基準件数、履歴平均/EWMA。 |
| F04 | 時刻付き過去指標の平均・最大・母標準偏差・EWMA・日単位の傾き。 |
| F05 | 同条件の過去成績率、相対着順、件数。 |
| F06 | 前走からの暦日差、期間出走数、距離差、surface・クラス変更。 |
| F07 | 出走当時の騎手の過去全体/条件別成績率・件数。 |
| F08 | 出走当時の調教師の過去全体/条件別成績率・件数。 |
| F09 | 固定馬集合内の事前指標順位・平均差・首位差・z値・既知頭数。 |
| F10 | 正規化済み基本条件、前走斤量差、固定馬集合の頭数。 |
| F11 | 馬×騎手、騎手×調教師の件数・頻度・成績率、乗替。 |
| F12 | 過去4角相対位置、順位改善、履歴平均・ばらつき。 |
| F13 | 明示閾値による排他的脚質区分と固定相手構成・割合。 |
| F14 | 正規化済み父/母父の産駒の条件別成績・件数・産駒数。 |
| F15 | 観測履歴量、有効値件数、完全性と初観測・初条件の区別。 |
| F16 | 過去体重lag、前2走差、平均/std、平均からの差・比。 |
| F17 | 坂路/ウッド別の距離付き区間時計・加速・期間回数・統計・自己/同日差。 |
| F18 | 距離付き過去ラップの前後半速度・差、個別とレースの上がり差。 |
| F19 | 同時点市場支持・順位・複勝幅・anchor間変化・券種総票差/率・馬連支持。 |
| F20 | 同枠/同調教師の相手数、事前能力差・順位。 |
| F21 | 過去全馬の有向加重対戦グラフ、PageRank、出走/相手数、収束診断。 |

7. 履歴窓、日数窓、半減期、条件キー、平滑化・最低件数・部分観測の扱い、指標方向、
   同値順位、脚質閾値、血統に自身を含めるか、市場anchor/整合幅、グラフの範囲・辺規則・
   減衰・damping・収束閾値・反復上限は明示パラメータとする。未指定の業務既定値を作らない。
   Hydraがこれらの実験設定を合成・検証する。手計算fixtureの値は実運用の既定値ではない。
   不明なオプション、無効な閾値、未収束はエラーとする。
8. 欠損補完、外れ値除外、丸め、カテゴリの数値化、例外レースの黙示除外は加えない。
   取得不足と本当に過去出走がない場合を分ける。未知馬のPageRankはNULLであり0ではない。
   条件基準の分散0、窓内欠測、分母0などは規則と理由を明示して欠損を保持する。
9. CLIは正規化済み・証跡付き入力を読む追加コマンドとして登録する。JSON変換は既存の
   serialization責務、物理I/Oは共通loader/saverへ置く。import/helpでデータを読まない。
   元データと既存出力を上書きせず、証跡とパラメータを計算出力と共に保存する。
10. 現存raw/Parquetの不足を埋めたように扱わず、実データの厳格な学習は必要な観測・版が
    そろうまで開始しない。21群の純粋計算テストと実データ学習の実績を区別する。
    現時点のモデルallow-listを21群の文字列・bool等へ自動的に広げない。

## Rationale

証跡付きの正規化観測から計算すれば、業務計算を実装しながら取得・物理保存との依存を分けられる。
個別ファイルの責務と既存APIを維持し、既存の中間表と監査を利用できる。
必須パラメータによって未決定の運用値を隠さず、計算式を手計算可能な入力で検証できる。

## Consequences

全21群に計算経路が加わる。利用者は値だけでなく根拠となる観測・完全性・設定を用意する必要がある。
証跡のない現存データは、この追加だけでは実データ学習へ利用できない。
厳格な過去時点再現ができること、モデルに追加価値があること、収益性があることは別々の検証である。
後日取得した履歴や現在の累積成績を過去行に配り、監査を通したことにはしない。

## Alternatives Considered

- 一部4群だけを先に計算する案は、ユーザーが21群を先に実装する方針を選んだため採用しない。
- 受信時刻を発表時刻やファイル更新時刻で代用する案、参考実験への緩和は不採用。
- 既存 `build_*` を新しい入力形式へ置換する案は既存の検証・保存利用者を壊すため採用しない。

## Validation / Follow-up

全21群で非自明な手計算期待値、欠損、0件/少件数、未来版・当該結果追加後の不変性を検証する。
基準fitの自己混入、群間の依存時刻、対象馬集合の欠落、改訂競合、未確認証跡の拒否を検証する。
PageRankは向き・総和・未知馬・未収束を、CLIは実ファイルの読込・保存と既存中間表への接続を検証する。
Ruff、mypy、pytest、guard回帰と独立レビューを行う。実データを実行していなければ明記する。
