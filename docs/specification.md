# 競馬AI 仕様決定事項

状態: 確定した範囲の仕様（2026-10-03）。[要件定義](requirements.md)を実行時の振る舞いへ落とした文書であり、予測モデルや購入画面が実装済みであることを示さない。設計候補の根拠と比較は[要件検討](discussions/2026-10-02-keiba-ai-requirements.md)および[モデル設計レビュー](discussions/2026-10-03-model-architecture-review.md)に記録する。

## 1. 対象と提案

| ID | 確定した仕様 | 対応要件 |
| --- | --- | --- |
| SPEC-01 | 購入案の対象をJRA平地重賞のG1・G2・G3に限定する。対象外のレースには購入を提案しない。 | REQ-01 |
| SPEC-02 | 各対象レースについて、発走5分前までに購入の可否を利用者へ提示する。購入する場合は、人が判断・購入できるよう券種、組合せ、各買い目の金額を提示する。システムは購入を実行しない。 | REQ-07 |
| SPEC-03 | 購入しない場合は全買い目の提案額を0円とする。期待利益が見込めないレースを見送れるようにする。購入の可否は提案の要約であり、購入する場合は買い目別の金額も必要とする。 | REQ-06, REQ-07 |
| SPEC-04 | 単勝・複勝・馬連・馬単・ワイド・3連複・3連単は、最初の調査・比較の範囲とする。各券種を購入案へ追加する順序と条件は、券種ごとの確率・オッズ・払戻を検証してから決める。 | REQ-08 |

発走5分前は**提案が完了する期限**である。入力の取得、予測、買い目計算、提示には処理時間を要するため、使用できる最新データの固定時刻は別に定める。発走時刻変更とデータ取得遅延の扱いも未決定である。

## 2. 購入額と記録

| ID | 確定した仕様 | 対応要件 |
| --- | --- | --- |
| SPEC-05 | 同一レースで記録済みの実購入額と追加提案額の合計を5,000円以下にする。 | REQ-05 |
| SPEC-06 | 暦年の実購入額累計と当該提案額の合計を100,000円以下にする。払戻金をこの年間購入可能枠へ加算しない。 | REQ-04 |
| SPEC-07 | 期待利益と損失リスクの両方を購入額決定に反映する。年間の純損失額に基づく追加停止条件は設けない。 | REQ-06 |
| SPEC-08 | 人が買うため、提案額と実際の購入額を区別して管理する。以後の購入可能額は、レース内・年間ともに実購入額の累計で判定する。実購入額が把握できず上限を確認できない場合は、購入を提案しない。 | REQ-04, REQ-05, REQ-07 |

馬券の発売単位は[JRAの規則](https://www.jra.go.jp/dento/comparison.html)に従い100円単位とする。購入経路によって一回の最低購入額や手数料が異なるため、経路固有の条件は経路を選定した後に仕様化する。返還があっても、購入済みの額面は年間の購入額累計から減らさない。回収率と手数料の集計定義は第4節に記す。

## 3. 予測とデータの境界

| ID | 確定した仕様 | 対応要件 |
| --- | --- | --- |
| SPEC-09 | まず入力データの取得範囲、発表・受信時刻、欠損、結果と払戻の意味を調査する。その後、市場オッズの基準方法、教師ありの着順確率・分布、購入額の最適化の順に開発・比較する。 | REQ-09 |
| SPEC-10 | 予測に使う情報は、提案用の入力固定時刻までに利用可能だったものに限定する。結果や事後の最終オッズを当該レースの予測特徴量に使わない。 | REQ-10 |
| SPEC-11 | 市場オッズを比較基準として同じ判断時点で予測品質を評価する。確率推定の改善と回収率の改善を別々に確認する。 | REQ-03, REQ-11 |
| SPEC-12 | 手元のSQLite原本に発走前オッズ履歴があるかは未確認とする。履歴の保存を確認できない期間は、その時点のオッズを使うバックテストの対象としない。 | REQ-12 |

予測MVPには[ADR-004](decisions/ADR-004-select-market-adjusted-win-model.md)に定める市場補正型の単勝確率モデルを採用する。同じ入力固定時刻の単勝オッズ逆数をレース内で正規化した市場基準を、発走前に利用できた特徴量で小さく補正する。購入案へ使う券種はまず単勝に限定し、見送りを許す。七券種の調査・比較は継続する。発走前オッズ履歴がなく同時点を再現できない期間は、最終オッズで代用してモデルの優位性や収益を評価しない。

連勝式の買い目を評価する際は、対象組合せが同時に的中する確率と払戻の見込みが必要となる。そのための2・3着の条件付き確率、払戻変動、券種別の的中条件は拡張時に検証する。[券種ごとの的中条件](https://www.jra.go.jp/kouza/beginner/baken/)、[払戻・同着・返還の規則](https://www.jra.go.jp/kouza/baken/index.html)

## 4. 検証

| ID | 確定した仕様 | 対応要件 |
| --- | --- | --- |
| SPEC-13 | 過去から未来へ進む時系列の分割で検証し、各評価レースの時点で利用可能だった情報だけを再現する。市場基準と学習モデルは同じ時点・同じ評価対象で比較する。 | REQ-10, REQ-11 |
| SPEC-14 | 予測品質としてLog Loss、Brier Score、確率校正を同じ評価レース・判断時点の市場基準と比較して報告する。 | REQ-03, REQ-11 |
| SPEC-15 | 購入結果として暦年の購入額・払戻額・回収率・利益・購入レース数・的中率・最大ドローダウン・最大連敗・資金推移を報告する。購入額0円の期間は回収率を数値化せず、購入件数とともに示す。 | REQ-02, REQ-11 |

予測MVPの比較は、レース単位の時間順Walk-forwardで行い、勝者Log Lossの同時点市場との差を主指標とする。差にはレース単位の対応ありbootstrapによる95%信頼区間を付け、上限が0未満のときだけ市場超過の証拠とする。全馬の多クラスBrier Scoreと確率校正も報告する。1着同着と入力固定後の発売対象馬の変更は、単独勝者モデルの主指標から除き件数・理由を報告する。購入結果は別の方策評価とし、購入判断に使ったオッズと事後の精算に使った確定払戻を区別する。

暦年の券面回収率は `確定払戻・返還に基づく受取額（特払いを含む）÷額面購入額`、純利益は `同受取額−額面購入額−手数料` とする。返還後も額面購入額は減らさず、特払いを通常払戻と重複計上しない。手数料が未確認の期間は純利益を確定値として報告しない。最大ドローダウンは年初0円からの累積純損益が過去最高値から下がった最大額（円）とする。過去検証の仮想購入と実購入の実績は分けて報告する。詳細は[ADR-004](decisions/ADR-004-select-market-adjusted-win-model.md)に記す。評価対象期間と実運用開始の条件、実際の口座残高の追跡方法は未決定である。発走前オッズが残っていない期間を、同時点の購入判断を再現したバックテストとして報告しない。

## 5. 設計レビュー中の事項

市場補正型のレース内単勝確率モデルは予測MVPとして選定済みである。CatBoost/LightGBMとPlackett–Luce、条件付き2・3着モデル、オッズ推移、Closing Odds Model、Jev、Fractional Kellyと他の数理最適化は、拡張または比較候補である。正の期待値を判定する際の安全余裕、複勝・ワイドの払戻範囲、同着・取消・返還が購入判断へ与える影響、リスク尺度、推論時間の数値目標、購入経路は未決定である。実装前に[現行アーキテクチャ](../ARCHITECTURE.md)とAccepted ADRを確認する。
