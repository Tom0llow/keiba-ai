# 競馬AIの要件検討（2026-10-02）

状態: 議論中。合意事項と検討案を区別する。回収率100%以上は目標であり、達成を保証する仕様ではない。

## 1. 目的と合意事項

| 項目 | 合意内容 |
| --- | --- |
| 対象 | JRAの平地重賞。障害重賞、地方競馬、海外競馬は対象外。 |
| 収益目標 | 暦年（1月～12月）の回収率100%以上を目指す。 |
| 年間予算 | 馬券の購入額累計を10万円以内にする。払戻金を得ても購入額上限は増やさない。データ契約費はこの枠に含めない。 |
| レース当たりの上限 | 全買い目の購入額合計を5,000円以内にする。 |
| 購入しない選択 | 可能。期待値が低いレースは見送る。 |
| 配分方針 | 期待利益と損失リスクの両方を考慮する。年間の購入額上限に加えた純損失による途中停止条件は設けない。具体的なリスク尺度は未決定。 |
| 判断時刻 | 発走5分前までに購入案を提示する。その後の購入操作は人が行う。 |
| 検討する券種 | 単勝、複勝、馬連、馬単、ワイド、3連複、3連単。これらを最初の比較対象に含める。 |
| データ | `data/raw/race.db` は利用中のJVLinkToSQLiteで作成した。具体的な取得範囲と発走前オッズ履歴の保存状況は確認中。追加の有料データ契約も必要なら検討でき、その費用は馬券予算に含めない。 |
| 開発順 | データの時点確認と勝敗要因の探索 → 市場オッズを使う基準方法 → 教師あり学習による着順分布 → 馬券と購入額の最適化。 |

回収率の計算式は「対象年の払戻金合計 ÷ 対象年の購入額合計 × 100」を候補とする。購入額が0円の年は回収率を定義せず、購入件数とともに報告する。返還金、特払い、データ費の扱いは評価仕様を確定する際に明文化する。馬券だけの年間純損失は「購入額累計 − 払戻・返還額」であり、購入額累計が10万円以下なら最大損失も10万円以下となる。データ契約費と投票手数料を含む総費用は別に扱う。

## 2. ユーザー案①への評価

ユーザー案は「各馬の1着・2着以内・3着以内の確率を教師あり学習で推定し、予算内で期待値を最大化する買い方を数理最適化で選ぶ」。予測と購入判断を分ける構成は採用候補とする。ただし、次の2点を補う。

### 連勝式には複数頭の同時着順確率が必要

単勝の評価には各馬の1着確率、複勝には発売開始時の出走頭数に応じて2着以内または3着以内の確率を使える。一方、馬連・馬単・ワイド・3連複・3連単の的中確率は、各馬単独の確率から一意に求まらない。例えば馬連の「AとBが1・2着」の確率には、AとBの**同時**着順が必要である。[JRAの券種定義](https://www.jra.go.jp/kouza/beginner/baken/)

したがって、同着のない通常結果では、予測の主な出力を「上位3頭の順序付き組合せに対する整合した確率分布」とする案を検討する。各馬の1着・2着以内・3着以内の確率は、そこから集計できる。初期の比較候補は、レース内の馬の強さから順序付き着順確率を構成する Plackett–Luce 型モデルと、市場オッズに基づく基準方法である。Plackett–Luce は計算しやすい順位モデルだが、実際の競馬の着順分布に十分合うかは検証が必要。[順位モデルの研究例](https://proceedings.mlr.press/v97/gu19a/gu19a.pdf) 同着では複数の的中組合せが発生するため、確率・期待利益の近似方法を別途決め、実績精算はJRAの確定払戻に従う。[JRAの同着時のルール](https://www.jra.go.jp/kouza/baken/index.html)

### 期待値だけでは賭け金の集中を防げない

買い目ごとの期待利益は「払戻額の期待値 − 購入額」である。的中時の払戻額の条件付き期待値を推定できれば、「的中確率 × 的中時の払戻額の条件付き期待値 − 購入額」と表せる。複勝・ワイドの発走前オッズには上下限があり、的中した相手の組合せでも払戻が変わるため、条件付き払戻の見込み方や保守的な下限の採用を別途決める。[複勝オッズの説明](https://targetfaq.jra-van.jp/faq/detail?category=109&id=436&site=SVKNEGBV)、[ワイドオッズの説明](https://jra-van.jp/fun/baken/index17.html)

[JRAの100円単位の発売](https://www.jra.go.jp/dento/direct/instructions.html)と予算上限だけで、期待利益の合計を線形に最大化すると、最も期待利益が高い1点に上限額が集中し得る。年間の損失変動や残りレースの機会も考えるなら、購入見送り、推定誤差への余裕、損失リスク、年間予算の配分を別に決める必要がある。期待利益と損失リスクの両方を考慮する方針は合意したが、具体的なリスク条件は未決定。

さらに、発走5分前のオッズは確定払戻ではない。購入案はその時点までに取得したオッズで作り、検証時の収益は確定した払戻金で計算する。同着、出走取消・競走除外、返還、特払いも券種のルールに従う。[JRAの馬券・払戻ルール](https://www.jra.go.jp/kouza/baken/index.html)

## 3. モデルを作る前に何を調べるか

勝った馬だけを集計しても、勝てなかった出走馬との違いや購入判断時に観測できた情報は評価できない。まず対象レースと全出走馬を単位に、予測時刻までに利用可能だった情報、欠損、データの更新時刻、着順・払戻の定義を確かめる。その上で勝敗要因を探索し、市場オッズだけを使う基準方法を作る。基準方法より改善するかを測るため、教師ありモデルも早期に小さく作る。

教師あり学習を最初の予測方法とする。過去の出走情報と確定結果から着順確率を学べ、確率の校正と券種別の評価を直接行えるためである。強化学習は、現時点の単一レースの「予測 → 購入案」には必要性が確認できない。将来、連続するレース間の資金配分などに教師あり学習と明示的な最適化では扱いにくい問題が生じた場合に再検討する。多項ロジットなどの統計モデルも、教師あり学習の有力な比較対象とする。市場の予想を表すオッズとの比較・組合せには競馬予測の先行研究があるが、このプロジェクトでの有効性は未検証である。[Benterの研究報告](https://datagolf.com/static/blogs/benter_paper.pdf) 学習対象を重賞のみにするか、一般の平地競走を含めるかは比較し、評価対象は合意済みの平地重賞に固定する。

軽量なレース内確率モデルと順位分布の計算を第一候補とし、必要なら木系モデル等を比較する。特定のアルゴリズムや外部ライブラリは、データの品質と基準方法の結果を見る前に確定しない。推論時間だけでなく、データ取得、特徴量計算、買い目生成、人に提示するまでの所要時間を測り、発走5分前の締切を満たす必要がある。

## 4. Jevの位置づけ

TypeSafe AIが2026-09-15に早期提供を発表した Jev は、文章生成型のLLMではなく、入力から型付きの選択と確率を返す意思決定モデルである。[公式発表](https://typesafe.ai/blog/introducing-system-one-models-and-jev) 提供元は応答時間70～500ミリ秒を公表しているが、米西海岸での測定であり、日本でのデータ取得から提案提示までの時間を保証しない。[公式発表の測定条件](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

公式資料は数値精度の弱さと、別々の質問で出した確率間の恒等式が保証されない点を明記する。したがって、Jevの出力をそのまま馬券の期待値計算へ入れる方法は採用せず、競馬の過去結果で校正・比較する実験候補にとどめる。[Jevの既知の制約](https://docs.typesafe.ai/model-jaggedness/jev-1.13) APIへのアクセス、利用料金、利用条件、外部送信、遅延も調査が必要である。[公式モデル仕様](https://docs.typesafe.ai/models)

## 5. データと検証の成立条件

リポジトリにはレースデータの SQLite 原本から35表を無加工で Parquet に書き出す仕組みと物理定義がある。予測モデルはまだない。[現行構成](../../ARCHITECTURE.md)、[物理定義](../table-definition/README.md) 2026-10-01の評価では原本のレース日付キーの最大値が2026-03-01で、取得元、更新頻度、列の業務上の意味は未確認だった。[データ評価記録](../data-assessment/race-db-2026-10-01.md) 今回ユーザーから、`data/raw/race.db` は JVLinkToSQLite の出力であると確認した。ただし取得設定と、そのファイル以外の履歴保存先は未確認である。

予測用データには少なくとも、対象レースと出走馬、レース前に確定した過去成績・馬場・騎手等の情報、発走5分前以前に取得した各券種のオッズ、確定着順、確定払戻、出走取消等の例外情報が必要になる。各項目の発表時刻と受信時刻を管理し、結果や最終オッズが予測特徴量へ混入しないようにする。既存表にこれらが十分含まれるか、列名から推測して確定しない。例えば現行の[単複オッズ表](../table-definition/NL_O1_ODDS_TANFUKUWAKU.md)の物理主キーはレース識別子のみで、時点を区別するキーはない。この表だけで発走5分前の履歴を復元できるとは判断しない。

[JVLinkToSQLiteの公開説明](https://jra-van.jp/dlb/sft/lib/jvl_tosqlite.html)によると、このツールはJRA-VANのデータをSQLiteへ変換する。[作者の設定仕様](https://github.com/urasandesu/JVLinkToSQLite/wiki/SettingXml-Spec)では時系列オッズ `0B41`・`0B42` と全賭式の速報オッズ `0B30` が初期設定で無効である。一方、[作者が示す時系列オッズ表](https://github.com/urasandesu/JVLinkToSQLite/wiki/RT_O1_ODDS_TANFUKUWAKU)は発表時刻を主キーに含む。現行の[35表の目録](../table-definition/README.md)にこの時系列表はないため、手元に別の保存先があるか、当時の取得設定がどうなっていたかを確認する。

JRA-VAN Data Lab. の現行仕様では、中間オッズの時系列データは単複・枠連と馬連が提供期間1年、ワイド・馬単・3連複・3連単を含む速報オッズは提供期間1週間とされる。選定した全券種を複数年さかのぼって発走5分前の条件で検証するには、別の履歴提供元を確認するか、開催中に取得・保存して検証期間を積み上げる必要がある。時系列データがあっても5分前ちょうどの記録が存在するとは仮定せず、判断時点までに受信した最新値を使う。[JRA-VAN公式データ仕様](https://jra-van.jp/dlb/sdv/sdk/JV-Data4901.pdf)

JRA-VANの[利用規約](https://jra-van.jp/info/rule.html)には取得情報の利用範囲に関する条件がある。手元での分析と、馬の履歴やオッズを Jev 等の外部APIへ送る処理は同じ扱いとは限らない。外部送信を検討する前に契約上の可否を確認する。

検証案は次のとおり。詳細な合格基準はデータの取得可能範囲を確認後に決める。

1. 時系列に沿って学習・調整・未使用期間を分ける。各レースの入力は発走5分前までに利用できた情報だけに限定する。
2. 市場オッズの基準方法と比較し、1着確率と買い目の確率校正、購入件数、購入額、払戻額、回収率、損益、最大損失幅を券種別・年別に示す。少数の高額的中だけに依存する結果かも調べる。
3. 確定払戻で損益を再現し、オッズ変動、欠損、取消・同着、データの取得遅れを検証する。過去データだけで発走5分前のオッズを復元できない期間は、実運用相当のバックテストとして扱わない。
4. 実購入前に、購入しない観測運用で発走5分前までに提案が出ることと、実際のオッズ・払戻との差を測る。

## 6. 実装要件のたたき台

下表は上記の合意事項をシステムで満たすための案であり、入出力形式や合格数値まで合意したものではない。

| ID | 要件案 |
| --- | --- |
| R-01 | 対象レースをJRAの平地重賞として識別し、対象外を購入案から除く。 |
| R-02 | 各レースの発走5分前までに利用可能だった入力とオッズの時刻・取得元を保持し、その時点の情報だけで予測する。 |
| R-03 | 対象券種の買い目について、通常の着順分布から的中確率を計算し、払戻の変動と同着を考慮して推定期待利益を評価する。計算できない券種は無理に補完しない。 |
| R-04 | 年間購入額累計10万円、同一レース合計5,000円、券種の発売単位を守り、損失リスクも考慮して購入額と購入見送りを選ぶ。 |
| R-05 | 人が購入を判断できるよう、券種・組合せ・金額・オッズの取得時刻・推定確率・予算残額を提示する。実際に買う時点でオッズが変わり得るため、購入可能な最低オッズの表示を検討する。 |
| R-06 | 提案額だけでなく実際の購入額と払戻・返還を記録し、暦年の予算残額と回収率を計算する。記録方法は未決定。 |

## 7. 次に決める事項

- 最適化に用いる損失リスクの尺度・許容値。購入額の年間配分、期待値の安全余裕を含む。純損失による追加の途中停止額は設けない。
- 複勝・ワイドの払戻範囲と同着について、購入前の期待利益・リスクをどう近似するか。確定後の損益は実際の払戻額を使う。
- JVLinkToSQLiteで取得できるデータの範囲・利用権と、発走5分前のオッズ履歴をどこまで保存しているか。追加の有料データ候補は条件・費用を確認してから決める。
- 回収率における返還・特払いの計算、購入額が少ない年の評価方法、実運用へ進むための必要な検証期間と不確実性の許容範囲。
- 人に提示する購入案の形式と、実際の購入・払戻を記録する方法。推定確率、参照したオッズの時刻、金額、年間残額、購入見送りの理由を表示項目の候補とする。

本書は議論と要件の記録であり、モデル、データ契約、購入方法の実装を決定するADRではない。
