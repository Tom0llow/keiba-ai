# 勝率・連対率・複勝率を予測できるか（2026-10-03）

## 質問と参照記事の位置づけ

質問: [「各馬の勝率、連対率、複勝率がわかっているとき、ある着順で決まる確率を推定する」](https://qiita.com/KuboTech/items/e61ca3161d6d0d99d339)のように、各馬の三つの率を予測できるか。可能ならどのモデルが適するか。

**予測自体は可能**である。ただし、いずれも真の確率が観測できるわけではなく、過去の着順から推定した確率として校正・検証する必要がある。参照記事は三つの率を**既知の入力**とし、1着A・2着B・3着Cとなる同時確率を近似する議論である。三つの率を学習するモデル、特徴量、評価結果は提示していない。記事末尾も、連対率・複勝率を考慮したPlackett–Luceは今後検討するとしている。[参照記事](https://qiita.com/KuboTech/items/e61ca3161d6d0d99d339)

## 出力する確率の定義

馬 `i` について、`p1_i = P(1着)`、`p12_i = P(2着以内)`、`p123_i = P(3着以内)` とする。記事の「勝率・連対率・複勝率」はこの三つに相当する。通常の同着がないレースでは、各馬について `0 ≤ p1_i ≤ p12_i ≤ p123_i ≤ 1`、全出走馬について `Σ_i p1_i = 1`、`Σ_i p12_i = 2`、`Σ_i p123_i = 3` が必要となる。`p12_i - p1_i` はちょうど2着、`p123_i - p12_i` はちょうど3着の周辺確率だが、他馬と同時に何着になるかは決まらない。[参照記事の前提](https://qiita.com/KuboTech/items/e61ca3161d6d0d99d339)

ここでの `p123_i` は**3着以内率**である。JRAの複勝馬券が的中する確率とは常に同じではない。発売開始時に8頭以上なら3着以内、5～7頭なら2着以内が複勝の的中条件であり、4頭以下では発売しない。[JRAの投票案内](https://www.jra.go.jp/dento/a/instructions/pdf/a-pat1.pdf?version=202501) 同着、取消、競走除外等がある場合は上の単純な順位制約と払戻の対応を別に定義し、精算ではJRAの確定結果を使う。[JRAの馬券ルール](https://www.jra.go.jp/kouza/baken/index.html)

## 比較するモデル

| 方法 | 三つの率の作り方 | 利点と制約 |
| --- | --- | --- |
| 3本の二値分類 | 各馬について「1着」「2着以内」「3着以内」を別々の教師ラベルにする。ロジスティック回帰やCatBoost等で学習できる。 | 実装しやすい比較基準。ただし `p1_i > p12_i` 等が起こり、レース内合計も `1, 2, 3` にならない可能性がある。後処理で直すと校正が変わり得る。[CatBoostの分類器仕様](https://catboost.ai/docs/en/concepts/python-reference_catboostclassifier) |
| 馬ごとの4クラス分類 | 「1着、2着、3着、4着以下」の確率を一度に予測し、上位2・3着以内の率を足し算する。 | 各馬内の大小関係は守れるが、レース全体の合計や買い目同士の整合性は保証しない。これは確率の足し算からの帰結である。 |
| レース内勝者モデル | 各馬にスコアを付け、レース内softmaxで1着確率を出す。 | `Σ_i p1_i = 1` を構造的に守るが、2着・3着は別途モデルが必要。市場オッズを基準に補正する小さな多項ロジットが初期候補。 |
| Plackett–Luce | 同じ馬の強さを用い、1着を選んで除き、残りから2着、次に3着を選ぶ。上位3頭の順序付き分布から三つの率を集計する。 | 順位間の整合性と組合せ確率が得られる軽量な基準モデル。ただし勝率だけから展開すると、予測したい連対率・3着以内率を独立に合わせられない。[順位モデルの研究論文](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/plackett.pdf) |
| 着順段階別の条件付きモデル | 1着、1着馬を除いた2着、上位2頭を除いた3着を、それぞれ異なるスコアで予測する。上位3頭の分布から三つの率を集計する。 | 順位間の整合性を保ちつつ、2・3着の傾向を別に学習できる。条件付きモデルにも校正と過学習の検証は必要。 |

実運用の第一候補は、**レース内の1着モデルを市場基準と比較し、次に着順段階別の条件付きモデルへ拡張する構成**である。3本の二値分類とPlackett–Luceは比較対象にする。初期の1着モデルは、同じ時点の単勝オッズから作る市場基準値 `q_i` を用いた `p1_i = softmax_i(log q_i + f(x_i))` のような条件付き多項ロジットを候補とする。`q_i` はオッズ逆数をレース内で正規化した**基準値**で、真の勝率ではない。まず小さな線形の補正関数 `f` を試し、非線形な木系モデルは保留データで改善を確認して比較する。[JRAの払戻規則](https://www.jra.go.jp/kouza/baken/index.html)

着順段階別モデルを `P(i,j,k) = P(1着=i) P(2着=j | i) P(3着=k | i,j)` と組み立て、異なる馬だけから各段階で選べば、上位3頭の順序付き分布が得られる。2着・3着は1着と別のスコア関数を学習する。`p1_i`、`p12_i`、`p123_i` は、その分布で馬 `i` がそれぞれ1着、上位2頭、上位3頭に入る組合せを足して求める。たとえば `p12_i = p1_i + Σ_{j≠i} P(1着=j)P(2着=i | j)` である。

単純なPlackett–Luceは2・3着にも1着と同じ強さを使うという仮定を置く。[Benterの競馬データによる検証](https://datagolf.com/static/blogs/benter_paper.pdf)では、これと同型のHarville計算が2・3着に系統的な偏りを示し、段階別パラメータで改善している。ただし、その論文の推定値をJRAへ流用せず、こちらの保留レースで検証する。参照記事の単純な周辺確率の積も、同一馬が複数順位を取れない制約を満たす同時分布にはならない。[参照記事](https://qiita.com/KuboTech/items/e61ca3161d6d0d99d339)

## 学習データと検証

教師データはレースごとの**全出走馬**と確定着順で構成する。各馬の過去走、距離・馬場、騎手・調教師、馬体重、当時の市場オッズ等は候補特徴量とするが、予測の入力固定時刻までに受信できたものだけを使う。1着・2着・3着の段階別モデルは、学習時には実際の先行着順を条件として学習し、推論時には全ての異なる上位3頭の組合せについて確率を集計する。18頭なら順序付き上位3頭は4,896通りで、モデル推論は軽くできる見込みだが、発走5分前の提示までの取得・特徴量作成・表示を含む時間は実測する。

重賞だけで学習する案と、JRAの他の平地競走も学習に使う案を比較し、評価対象は平地重賞に固定する。市場のみ、独自特徴量のみ、市場を補正するモデルを**同じ時点**で比較する。時系列のレース単位Walk-forwardで、1着・2着以内・3着以内それぞれのLog Loss、Brier Score、確率校正を確認し、連勝式へ使う前に組合せ確率も検証する。総和が `1, 2, 3` でも実際の頻度に合うとは限らない。最終的な馬券購入判断には、確率に加えて券種ごとの当時のオッズと確定払戻の見込みが必要である。[モデル設計レビュー](2026-10-03-model-architecture-review.md)

現在の`race.db`について発走前オッズ履歴の有無は未確認である。履歴のない期間を発走5分前の市場基準や収益の実運用相当のバックテストに使わない。モデル形式と特徴量の採否はデータ監査と保留期間の結果を見て決めるため、今回は[確定仕様](../specification.md)へ追加しない。
