主要3表の `MIN(rowid)=1`、`MAX(rowid)=COUNT(*)` を確認してから、各表に対し以下の非復元抽出を行った。`IN` 句は `?` を標本数だけ並べて束縛した。3表とも抽出した行番号すべてに行が一致した。選ばれた標本に対して `EXPLAIN QUERY PLAN` は `INTEGER PRIMARY KEY` 探索を示した。測定中にDBが変化しないことを前提とする。

```python
import random

samples = {}
sample_rowids = {}
for table, n in (
    ("NL_RA_RACE", 2048),
    ("NL_SE_RACE_UMA", 2048),
    ("NL_UM_UMA", 1024),
):
    last_rowid = con.execute(f'SELECT MAX(rowid) FROM "{table}"').fetchone()[0]
    rowids = sorted(random.Random(20261001).sample(range(1, last_rowid + 1), n))
    marks = ",".join("?" for _ in rowids)
    samples[table] = con.execute(
        f'SELECT * FROM "{table}" WHERE rowid IN ({marks})', rowids
    ).fetchall()
    sample_rowids[table] = rowids
```

各標本の全セルについて `value is None`、`isinstance(value, str)`、`isinstance(value, str) and not value.strip()` を数えた。日付の暫定検査は前後空白を除いた値がASCII数字8桁であることと、年・月・日に分解して `datetime.date` で実在日付になることを条件とした。RA・SE のイベント日付は `idYear + idMonthDay` を検査した。ゼロ8桁は不適合と分類したが、欠損扱いする規則は承認されていない。
